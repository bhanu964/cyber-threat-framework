# Cross-Platform Cyber Threat Framework

A centralized cybersecurity monitoring framework designed to demonstrate cross-platform endpoint monitoring, application-level security telemetry, persistent event storage, and real-time SOC visualization.

The project uses a macOS-based administrative control node and a Fedora Linux endpoint within a controlled cybersecurity laboratory environment.

---

## Overview

The LG9 Cross-Platform Cyber Threat Framework provides a centralized platform for collecting and monitoring security-related events generated by monitored endpoints.

The system consists of:

- A **macOS Control Node** acting as the administrator/SOC environment
- A **Fedora Linux Endpoint** acting as the monitored endpoint
- A **FastAPI backend** providing the telemetry and REST API layer
- An **SQLite database** for persistent device and security-event storage
- A **web-based SOC dashboard** for real-time monitoring
- A simulated **LG9 Finance** application for generating controlled security telemetry

The project demonstrates how security events can travel from an endpoint to a centralized monitoring system and be visualized by an administrator.

## API Endpoints

### System Status

```http
GET /api/status
```

Returns the current status of the control node.

### Register Device

```http
POST /api/devices/register
```

Registers a monitored endpoint.

Example:

```json
{
  "device_id": "FEDORA-01",
  "platform": "Fedora Linux",
  "role": "victim"
}
```

### Get Devices

```http
GET /api/devices
```

Returns all registered endpoints.

### Get Device

```http
GET /api/devices/{device_id}
```

Returns information about a specific endpoint.

### Heartbeat

```http
POST /api/devices/{device_id}/heartbeat
```

Updates the endpoint's last-seen timestamp and status.

### Create Security Event

```http
POST /api/events
```

Creates a new security event.

Example:

```json
{
  "event_type": "LOGIN_ATTEMPT",
  "source": "FEDORA-01",
  "target": "LG9-FINANCE",
  "severity": "low",
  "message": "Authentication attempt detected"
}
```

### Get Security Events

```http
GET /api/events
```

Returns recorded security events.

### Clear Events

```http
DELETE /api/events
```

Clears the stored security events.

## Running the Project Locally

### 1. Clone the repository

```bash
git clone https://github.com/YOUR_USERNAME/cyber-threat-framework.git
cd cyber-threat-framework
```

### 2. Create a virtual environment

```bash
python3 -m venv .venv
```

### 3. Activate the environment

macOS / Linux:

```bash
source .venv/bin/activate
```

Windows:

```powershell
.venv\Scripts\activate
```

### 4. Install dependencies

```bash
pip install -r requirements.txt
```

### 5. Start the FastAPI server

```bash
uvicorn backend.main:app --host 0.0.0.0 --port 8000 --reload
```

## Security Model

The project is designed as a **controlled cybersecurity laboratory demonstration**.

It focuses on:

- Application-level telemetry
- Endpoint visibility
- Centralized monitoring
- Security-event persistence
- Controlled authentication-event simulation
- Threat visualization

The framework does **not** implement system-wide keylogging, hidden credential collection, malware deployment, or covert surveillance.

Authentication and user-interaction data used during demonstrations should be fictional test data only.

## Deployment

The framework can be deployed as a centralized web service using platforms such as Render.

A cloud deployment allows:

```text
Remote Endpoint
       ↓
    Internet
       ↓
 FastAPI Backend
       ↓
 Security Database
       ↓
 SOC Dashboard
```

This enables multiple systems to access the same centralized security monitoring environment without requiring them to be connected to the same local network.
